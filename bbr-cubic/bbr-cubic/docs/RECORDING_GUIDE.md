# Recording Guide — Replication-Only Sequence

**One continuous terminal recording. No paper walkthrough, no slides — just the
project, the environment, and the already-executed experiment evidence.**

Every command below is **read-only** against already-generated files, except step 5
(`netns_topo.sh up`/`down`), which only creates/destroys Linux network namespaces —
it never touches anything in `outputs/`. **No experiment is rerun.** All data shown
was generated by the three runs logged in `docs/EXPERIMENT_LOG.md` and re-verified
intact by `scripts/verify_outputs.py`.

One terminal, one session:

```
wsl -d FairFlow-Ubuntu2204
cd /mnt/c/Users/PRAVEENA/OneDrive/Desktop/FairFlow_Replication
```
Say: "This is the FairFlow replication project, running inside a dedicated Ubuntu
22.04 WSL environment."

## 1. Project / environment / topology

**Command:**
```
ls scripts/ outputs/
```
Say: "Scripts, and the outputs folder with everything the experiments produced."

**Command:**
```
cat scripts/netns_topo.sh
```
Say: "This is our topology — Linux network namespaces and veth links standing in
for Mininet and the P4 switch, with `tc netem` setting the RTTs and a 15 megabit
bottleneck."

**Command** (safe, live, touches no saved results):
```
bash scripts/netns_topo.sh up
ip netns list
bash scripts/netns_topo.sh down
```
Say: "Bringing the topology up live, for real — sender, switch, three receivers —
then tearing it down. This doesn't touch any saved experiment data."

## 2. Experiment configuration

**Command:**
```
cat scripts/run_scenario.sh
```
Say: "One script per scenario: topology up, iperf3 BBR traffic, the QACK proxy if
enabled, then teardown."

**Command:**
```
grep -A2 "^Command:" docs/EXPERIMENT_LOG.md
```
Say: "These are the exact commands actually used — 120 seconds each, QACK enabled
at the 60-second mark."

**Command:**
```
ls outputs/no_qack*
```

## 4. QACK-static implementation

**Command:**
```
grep -n "STATIC_TARGET" scripts/qack_proxy.py
```
Say: "Static mode always targets connection 0 — the 80-millisecond flow."

## 5. QACK-dynamic implementation

**Command:**
```
grep -n "max(counters" scripts/qack_proxy.py
```
Say: "Dynamic mode picks whichever connection has the highest packet count right
now, every interval."

## 6. Evidence all three experiments were actually executed

**Command:**
```
ls -la outputs/*.json outputs/*.log
```
Say: "Every file all three runs actually produced, with real timestamps."

**Command:**
```
tail -5 outputs/qack_static_qack.log

```
Say: "35 real QACK packets fired in each run. Static always targets connection 0
by design — and in this run, dynamic's argmax logic also picked connection 0
every single time, because it genuinely had the highest packet count each round."
