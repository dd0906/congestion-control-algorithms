## `scripts/` — what each file does

| File | Purpose |
|---|---|
| `netns_topo.sh` | Builds/tears down the fast-path topology (5 network namespaces, veth links, RTT delays, bottleneck bandwidth). `up`/`down` args. Safe to run — never touches `outputs/`. |
| `run_scenario.sh` | Runs one full experiment scenario end-to-end (topology up -> iperf3 servers -> iperf3 BBR clients -> optional QACK proxy -> wait -> teardown), all in one continuous process. This is what actually produced everything in `outputs/`. **Do not rerun** unless you intend to overwrite results. |
| `qack_proxy.py` | The fast-path QACK mechanism — a Scapy raw-socket proxy that sniffs traffic and injects spoofed ACKs. Takes `static` or `dynamic` as its argument. This is the code that ran during the `qack_static` and `qack_dynamic` experiments. |
| `qack.p4` | The **original, intended** P4 data-plane design for QACK — written but never compiled or run, because the P4/BMv2 toolchain build didn't finish in time. Kept for an optional future higher-fidelity re-run. |
| `analyze_results.py` | Reads 3 raw iperf3 JSON logs for one scenario, computes Jain's Fairness Index over time, writes the `*_timeseries.csv`, `*_throughput.png`, and `*_summary.json` files. |
| `make_fig3.py` | Reads the 3 scenarios' `*_summary.json` files and produces `fig3_replication.png` (the paper's Fig. 3 equivalent). |
| `check_summary.py` | Small read-only helper — prints per-second throughput from a raw iperf3 JSON log. Used for quick verification/demo, not part of the core pipeline. |
| `verify_outputs.py` | Read-only script that checks every output artifact exists, parses correctly, and has the expected shape (row counts, PNG signatures, QACK-fire counts). Safe to rerun any time — never modifies anything. |
| `setup_sudoers.sh` | One-time provisioning script from earlier in the project, used to set up minimal passwordless sudo on the *original* Ubuntu 26.04 WSL distro (not the one experiments actually ran in). Historical; not needed for recording. |
| `patch_install_script.py` | One-time patch script from the (abandoned) P4/BMv2 toolchain build attempt — fixed package-name issues in `install-p4-dev.sh`. Historical; not needed for recording. |
| `run_smoketest.py` | A 9-byte placeholder file (`print(1)`) created early on to test sudo permissions. Not a real script — safe to ignore. |
| `README.md` | Short placeholder description of this folder from early in the project. |

## `outputs/` — what each file pattern is

All files use the prefix `no_qack_`, `qack_static_`, `qack_dynamic_`, or
`smoketest_` to identify which experiment run produced them.

| Pattern | What it is |
|---|---|
| `<scenario>_80ms.json` / `_40ms.json` / `_20ms.json` | Raw iPerf3 client output (JSON, `-J` flag) for the 80ms/40ms/20ms-RTT flow in that scenario. **The real measured data.** |
| `<scenario>_80ms.err` (etc.) | iPerf3 client stderr — all empty (0 bytes), meaning no errors during any run. |
| `<scenario>_recv{1,2,3}_server.log` | iPerf3 server-side logs for that scenario. |
| `<scenario>_qack.log` | Only exists for `qack_static` and `qack_dynamic`. The QACK proxy's own log — every QACK it fired, which connection it targeted, and the packet counters at that moment. **Direct evidence QACK actually ran.** |
| `<scenario>_timeseries.csv` | Per-second throughput for all 3 flows + Jain's Fairness Index, merged from the 3 JSON files. Generated by `analyze_results.py`. |
| `<scenario>_summary.json` | Average fairness index (overall / pre-QACK-enable / post-QACK-enable) for that scenario. Generated by `analyze_results.py`. |
| `<scenario>_throughput.png` | Chart: 3 throughput lines + fairness index over time. The paper's Fig. 4/5 equivalent. |
| `fig3_replication.png` | Bar chart comparing average fairness index across all 3 scenarios. The paper's Fig. 3 equivalent. Generated by `make_fig3.py`. |
| `smoketest_*` | A 10-second no-QACK pipeline sanity check run once before the real 120s experiments, to confirm the pipeline worked. Not otherwise analyzed — not part of the reported results. |
| `README.md` | Short placeholder description of this folder from early in the project. |

## `bbr_cubic/` — the separate BBR-vs-CUBIC coexistence experiment

A small, **fully isolated**, additional experiment connecting this project to a
different assigned topic ("SDN-Based Dynamic Bandwidth Arbitrator for Fair
Coexistence of BBR and CUBIC"). It reuses the same `FairFlow-Ubuntu2204`
environment but its own separate network namespaces/topology, and touches
**nothing** in the main project's `outputs/`, `scripts/`, or `docs/`. Read
`bbr_cubic/README.md` first if you only care about this sub-experiment, or
`docs/FINAL_STATE.md` sections 11-18 for a condensed summary alongside the QACK
results in the same document.

| Path | What it is |
|---|---|
| `bbr_cubic/README.md` | Overview of this sub-experiment and how it relates to the main QACK replication. |
| `bbr_cubic/EXPERIMENT.md` | Topology, configuration, exact commands used, and the congestion-control verification method. |
| `bbr_cubic/RESULTS.md` | The compact results table (throughput, retransmits, Jain's Fairness Index for both conditions) plus an honest discussion of the finding that CUBIC dominated BBR in this setup. |
| `bbr_cubic/RECORDING_GUIDE.md` | Tested, read-only command sequence + narration for demoing this sub-experiment. |
| `bbr_cubic/scripts/topo.sh` | Builds/tears down the 2-sender-1-bottleneck topology (`senderA`=BBR, `senderB`=CUBIC, `switch`, `receiver`). `up <rate_mbit> <delay_ms>` / `down` args. Safe to run — never touches `bbr_cubic/outputs/`. |
| `bbr_cubic/scripts/run_condition.sh` | Runs one full condition end-to-end (topology up -> iperf3 servers -> BBR+CUBIC client(s) -> live `ss -ti` congestion-control capture -> wait -> teardown). This produced everything in `bbr_cubic/outputs/`. **Do not rerun** unless you intend to overwrite results. |
| `bbr_cubic/scripts/analyze.py` | Reads the raw iperf3 JSON logs, computes Jain's Fairness Index and retransmit counts, writes the `*_timeseries.csv`/`*_summary.json` files and all 3 required graphs. |
| `bbr_cubic/outputs/solo_bbr_*`, `solo_cubic_*` | Baseline runs: BBR alone and CUBIC alone (no competition), 10 Mbit/s / 20ms. |
| `bbr_cubic/outputs/conditionA_*` | BBR + CUBIC coexisting, 10 Mbit/s bottleneck / 20ms RTT. |
| `bbr_cubic/outputs/conditionB_*` | BBR + CUBIC coexisting, 5 Mbit/s bottleneck / 50ms RTT. |
| `bbr_cubic/outputs/*_ss.log` | Raw kernel `ss -ti` output captured live during each run — the actual proof each sender used the congestion-control algorithm claimed (not inferred from the `iperf3 -C` flag). |
| `bbr_cubic/outputs/*_summary.json`, `all_summary.json` | Computed averages: throughput, Jain's Fairness Index, retransmits. |
| `bbr_cubic/outputs/smoketest_*` | An 8-second pipeline sanity check run once before the real experiments — not otherwise analyzed. |
| `bbr_cubic/graphs/bbr_vs_cubic_conditionA.png` | Required graph 1 — throughput + fairness over time, Condition A. |
| `bbr_cubic/graphs/bbr_vs_cubic_conditionB.png` | Required graph 2 — throughput + fairness over time, Condition B. |
| `bbr_cubic/graphs/bbr_cubic_fairness_comparison.png` | Required graph 3 — bar chart comparing fairness index across both conditions. |
